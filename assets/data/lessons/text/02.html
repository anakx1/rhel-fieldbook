Every process has three standard streams: stdin (0), stdout (1), and stderr (2). Redirection changes where they go. This is the mechanism behind most useful one-liners.

SyntaxEffect
cmd > fileSend stdout to file, truncating it first.
cmd >> fileAppend stdout to file.
cmd 2> error.logSend stderr to a file.
cmd 2>&1Send stderr to wherever stdout currently points.
cmd > out.log 2>&1Send both streams to the same file.
cmd > /dev/nullDiscard stdout. /dev/null is the bit bucket.
cmd1 | cmd2Pipe stdout of cmd1 into stdin of cmd2.
cmd | tee fileWrite to the terminal and to a file at the same time.

A pipe connects processes; it does not create a temporary file. This is why pipelines can process enormous data with small memory footprints. Each stage should do one job well.

terminal · stdout, stderr, and a pipe

grep -i error /var/log/messages | tail -n 5
Order matters

cmd 2>&1 > file does not do what most people expect. Redirections are evaluated left to right; send stdout first, then point stderr at it: cmd > file 2>&1.
