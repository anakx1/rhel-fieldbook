find walks a directory tree and tests each path. Start with a bounded tree, add a type and name, and only then widen. An unbounded find / during an incident is a good way to add I/O pressure while learning very little.

terminal · find with intent
find /var/log -type f -name "*.log"
find /etc -type f -name "*.conf" -newermt "-7 days"
find /home -type f -perm /o+w

The last command looks for world-writable files. -type f excludes directories, -name matches the basename, and -newermt filters by modification time. Use -maxdepth when you mean one level, and quote patterns so the shell does not expand them first.

Find first, act second

Run a find expression without an action, inspect the list, then add -exec or a pipe. Batch destruction is not a learning outcome.
