"Disk full" is three different problems wearing the same jacket:

  1. Blocks exhausted — no free data blocks. df -h shows 100% use.
  2. Inodes exhausted — many tiny files consume metadata. df -h may show free space while df -i shows 100% inode use.
  3. Deleted but open — a process still holds a deleted file. Space is not reclaimed until the file descriptor closes. lsof +L1 finds these.
terminal · capacity forensics
df -hT
df -i
sudo du -xhd1 /var | sort -rh | head
sudo lsof +L1

du -x stays on one filesystem, which prevents it from wandering into other mounts. -d1 limits depth. Sorting by human-readable size is convenient but not perfectly numeric; use du -sk and sort -n when precision matters.

On RHEL, /var is the usual suspect: logs, journal, package cache, containers, and application data. Do not delete blindly. Identify the owner, apply the service's retention tool, and fix the cause. A log that grows unbounded will fill the disk again tomorrow.

Use the right cleanup tool

dnf clean all clears package cache. journalctl --vacuum-size=500M trims the journal. Application logs have their own rotation policy. rm is not a retention strategy.
