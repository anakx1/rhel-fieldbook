DNF resolves dependencies and presents a transaction. Read it. Confirm that the package count, download size, and removals match your intent, especially on a production host.

terminal · install, update, remove
sudo dnf install httpd
sudo dnf update
sudo dnf remove httpd
sudo dnf history
sudo dnf history info 42
sudo dnf history undo 42

dnf update without arguments updates all installed packages. That may be correct for a routine patch window and wrong for a targeted fix. For a single package, name it: sudo dnf update openssl. Use dnf check-update to preview available updates without applying them.

Every transaction gets a history ID. This is invaluable during an incident: you can see what changed, when, and by which user. Undo is not magic — it attempts to reverse the transaction, and dependency conflicts may prevent a clean rollback. Snapshots and tested backups remain the real safety net.

Do not pipe the internet into your shell

Adding random repositories or running vendor install scripts bypasses signed package policy and change tracking. Prefer official repositories; if you must add a third party, document the source and trust decision.
