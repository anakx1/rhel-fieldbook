RHEL ships with firewalld enabled. It is not an obstacle to work around; it is part of the service deployment. Open only the service or port that is required.

terminal · inspect and open a service
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
sudo firewall-cmd --list-services

--permanent writes to the persistent configuration. Without it, the change is runtime-only and disappears on reload or reboot. Many "it worked yesterday" firewall stories are missing --permanent; many "it still doesn't work" stories are missing --reload.

For a nonstandard port, add it explicitly: --add-port=8080/tcp. Prefer service definitions when available because they carry the correct ports and protocol semantics. Disabling the firewall to test is a bad habit that eventually reaches production.

Do not stop firewalld to prove a point

If stopping the firewall "fixes" the problem, you have learned that the rule set is involved. Now inspect zones, services, ports, and source addresses — and add the narrowest rule that works.
