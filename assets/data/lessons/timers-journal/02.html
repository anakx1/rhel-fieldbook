A timer does not contain the command. It triggers a unit, usually a service with the same base name. Keep the service responsible for doing the work and the timer responsible only for scheduling.

/etc/systemd/system/fieldbook-backup.service
[Unit]
Description=Fieldbook nightly backup

[Service]
Type=oneshot
ExecStart=/usr/local/bin/fieldbook-backup
/etc/systemd/system/fieldbook-backup.timer
[Unit]
Description=Run fieldbook backup nightly

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
Unit=fieldbook-backup.service

[Install]
WantedBy=timers.target

OnCalendar accepts calendar expressions, not only intervals. OnUnitActiveSec=1h is a monotonic timer measured from the last activation; OnCalendar follows wall-clock time. Use Persistent=true for jobs that must catch up after downtime, and add RandomizedDelaySec when many hosts would otherwise hit the same service at once.

Install the right target

Timers install into timers.target, not multi-user.target. Enabling the timer creates the link; enabling only the service does not schedule anything.
