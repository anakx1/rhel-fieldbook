systemd timers are the native scheduler on RHEL. They trigger units, record results in the journal, and participate in the same dependency and enablement model as every other service.

NeedTimerCron
Journal integrationNativeMail or manual logging
Dependency orderingsystemd unit graphNone
Catch-up after downtimePersistent=trueanacron separately
Simple per-user scheduleUser timers or system unitsPer-user crontab is simpler

Use timers for system work that benefits from supervision and logs. Use cron when a simple per-user cadence is genuinely enough. Do not run both for the same job.

terminal · inspect timers
systemctl list-timers --all
systemc-analyze calendar "*-*-* 02:00:00"

The second command has a deliberate typo: it will fail. Read errors as evidence too. The real command is systemd-analyze calendar.
