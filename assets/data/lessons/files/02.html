cp copies content. mv renames or relocates. rm unlinks. The first two are generally reversible; the last one usually is not.

CommandBehavior
cp file copyCopy a file. Existing destination is overwritten without asking.
cp -i file copyPrompt before overwriting.
cp -r dir newdirCopy a directory recursively. Does not preserve ownership/timestamps by default.
cp -a dir backupArchive mode: recursive, preserves mode, ownership where permitted, timestamps, links, and ACLs.
mv old newRename or move. Same-filesystem moves are metadata operations and are fast.
rm fileRemove a file. No trash can by default.
rm -i filePrompt before removal.

There is no recycle bin for the shell. Build the reflex of checking the target before pressing Enter:

terminal · a safer rm workflow
ls -ld ~/lab/old-project
rm -ri ~/lab/old-project

Aliases can make rm interactive for your user, but aliases do not apply inside scripts, during sudo, or when another user runs the command. Safety has to live in the habit, not in an alias.

The two commands that end careers

Be extremely careful with rm -rf and dd. A misplaced space or an unset variable can widen the target. In scripts, quote paths and use set -u so an empty variable cannot become an empty path.
