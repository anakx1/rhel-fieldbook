Creating files is easy. Creating them in the wrong place, with the wrong owner, is also easy. Start by making a deliberate directory tree:

terminal · build a workspace
mkdir -p ~/lab/notes ~/lab/logs ~/lab/archive
touch ~/lab/notes/day1.txt
ls -lR ~/lab

mkdir -p creates missing parents and does not fail if the target already exists. touch updates timestamps, or creates an empty file if none exists. ls -R walks recursively; use it on small trees, not on /.

Before acting on an unfamiliar file, ask what it actually is and when it changed:

terminal · inspect metadata
file ~/lab/notes/day1.txt
stat ~/lab/notes/day1.txt
du -h ~/lab/notes/day1.txt

file reads magic bytes and guesses the content type. stat reports inode number, size, permissions, and three timestamps: access, modify, and change. du reports disk usage, which can differ from apparent size because of block allocation, sparse files, and compression.

Size is not one number

The apparent size from stat is not always the space consumed on disk. Use du for block usage and df for filesystem capacity.
