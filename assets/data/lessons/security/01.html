Traditional permissions ask who you are and what mode bits allow. SELinux adds a label-based policy: even root can be denied if the process domain is not allowed to access the target type. This is mandatory access control, and it is one of the reasons RHEL is harder to casually compromise.

Modes:

  • Enforcing — policy is applied and denials are blocked and logged.
  • Permissive — policy is evaluated and denials are logged, but access is allowed. A diagnostic mode, not a destination.
  • Disabled — SELinux is off. Requiring a reboot and losing protection is not a troubleshooting step.

A context looks like system_u:object_r:httpd_sys_content_t:s0. The type is the part you will work with most: httpd_sys_content_t for web content, ssh_home_t for SSH files, user_home_t for home data. Files moved into a new location keep their old context; files created in the right location usually inherit the correct one.

Never start by disabling SELinux

Disabling enforcement hides the actual mismatch and often creates a false success that fails again on the next host. Read the denial, fix the label, port, or boolean, then keep enforcing.
