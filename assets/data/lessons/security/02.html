When SELinux blocks something, it writes an AVC denial to the audit log. The denial names the source domain, target type, and requested permission. That is enough to choose a fix.

terminal · find recent denials
sudo ausearch -m AVC -ts recent
sudo journalctl -t setroubleshoot --since "1 hour ago"
sudo sealert -a /var/log/audit/audit.log

The most common causes and their honest fixes:

SymptomLikely causeCorrect fix
Web content returns 403 after being copied from /homeWrong file type/contextrestorecon -Rv /var/www/html
Service cannot bind a nonstandard portPort not allowed for that domainsemanage port -a -t http_port_t -p tcp 8080
Service needs to make an outbound connectionBoolean disabledsetsebool -P httpd_can_network_connect on
Custom app files keep the wrong labelNo matching file-context rulesemanage fcontext -a ... then restorecon

restorecon applies the policy's expected context to a path. chcon sets a label manually, but it is temporary and can be overwritten by a relabel. Prefer semanage fcontext plus restorecon for persistent custom paths.

terminal · custom web root
sudo semanage fcontext -a -t httpd_sys_content_t "/srv/site(/.*)?"
sudo restorecon -Rv /srv/site
ls -Z /srv/site

Booleans toggle prewritten policy behavior. List them, inspect the description, then set persistently with -P:

terminal · booleans
getsebool -a | grep httpd
sudo setsebool -P httpd_can_network_connect on

Do not enable broad booleans because a search result suggested it. Understand the capability you are granting, and prefer the narrowest one that works.
