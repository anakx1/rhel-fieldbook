A directory is not necessarily part of the root filesystem. It can be the attachment point for a separate disk, an LVM volume, a network share, or a virtual filesystem. Ask the system what is mounted where:

terminal · see the mount landscape
findmnt /
df -hT
lsblk -f

findmnt shows the mount tree. df -hT shows capacity and filesystem type in human units. lsblk -f shows block devices, their filesystems, labels, UUIDs, and mount points. Learning to read these three together is a core administration skill.

This is also how you diagnose "the disk is full" correctly. A full /var does not mean the root filesystem is full — it may be a separate volume. df reports filesystem-level usage; du reports the size of directories. You need both to find the culprit.

Do not delete from /var blindly

Logs, package caches, and application data live under /var. Deleting the wrong thing can break services or destroy evidence. Identify the owner and the retention policy first.
