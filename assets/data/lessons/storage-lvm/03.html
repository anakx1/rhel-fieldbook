When the volume group has free extents, extending an LV is online work. On XFS, use -r so LVM resizes the filesystem after extending the volume.

terminal · grow the LV and filesystem
sudo vgs
sudo lvextend -r -L +2G /dev/vgdata/lvapp
df -h /app
findmnt /app

If the VG is out of free space, add another PV with vgextend vgdata /dev/sdc before extending again. If you need more than one LV, keep the VG as the pool and size each LV deliberately.

Swap can live on a dedicated LV, a partition, or a file. The same activation commands apply. Plan swap as a safety margin, not as a way to avoid diagnosing memory pressure.

terminal · swap on an LV or device
sudo lvcreate -n lvswap -L 2G vgdata
sudo mkswap /dev/vgdata/lvswap
sudo swapon /dev/vgdata/lvswap
swapon --show
RHEL 9 vs RHEL 10

This workflow is identical on both releases. The version difference is not in the LVM verbs; it is in the surrounding platform. Keep your recovery media aligned with the installed major release before changing storage.
