Bash conditions use [[ ... ]] for strings and files, and arithmetic expressions for numbers.

conditionals
#!/bin/bash
set -euo pipefail

file="${1:-/etc/os-release}"

if [[ ! -r "$file" ]]; then
  echo "cannot read: $file" >&2
  exit 1
fi

if [[ -s "$file" ]]; then
  echo "file has content: $file"
fi

load=$(cut -d' ' -f1 /proc/loadavg)
if (( load > 4 )); then
  echo "load is elevated: $load"
fi

Common file tests: -e exists, -f regular file, -d directory, -r readable, -s non-empty. String tests: ==, !=, -z empty. Numeric comparisons inside (( )) use >, <, >=, and so on.

Loops process collections without copy-paste:

loops
for unit in sshd chronyd firewalld; do
  if systemctl is-active --quiet "$unit"; then
    echo "OK   $unit"
  else
    echo "FAIL $unit"
  fi
done

Prefer reading command output rather than parsing human-oriented tables. Use systemctl is-active --quiet for a clean exit status; do not grep the output of systemctl status, which is designed for people and changes between versions.

Exit codes are the API

A script should return 0 on success and non-zero on failure. Automation depends on this. Printing "ERROR" but exiting 0 is a lie that breaks pipelines.
