These commands are not a ritual. Each answers a different question. Run the ones that match the symptom, in an order that rules out the broadest causes first.

terminal · first-pass health check
uptime
systemctl --failed
journalctl -p err -b --no-pager | tail -n 20
df -hT

free -h
ip -br addr

sudo ss -tulpn
sudo dnf history | head
QuestionCommandWhat good looks like
Is the system under pressure?uptime, free -hLoad is proportionate; memory is not exhausted.
Did a unit fail?systemctl --failedEmpty list, or a specific unit to investigate.
What errors are recent?journalctl -p err -bA short, time-correlated set of messages.
Is storage exhausted?df -hT, df -iFree blocks and inodes on every mount.
Is the network configured?ip addr, ip routeExpected address and a default route.
Is anything listening?ss -tulpnThe expected service on the expected port and address.
What changed?dnf historyA known transaction, or no recent package change.

Do not run all ten on every issue. If a user cannot reach a website, start with the listener, the firewall, and the route. If the host is slow, start with load, memory, and I/O. If a service will not start, start with its unit status and journal.
