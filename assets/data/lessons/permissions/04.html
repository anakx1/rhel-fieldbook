Traditional permissions have exactly one owner and one group. When you need to grant a second user or a second group access, an access control list is the honest tool.

terminal · grant a second group access
sudo setfacl -m g:audit:r report.txt
getfacl report.txt
sudo setfacl -m u:analyst:rw report.txt

An ACL entry appears as a + at the end of the mode string. getfacl shows the entries; setfacl -x removes them. Default ACLs on a directory can propagate access to newly created files.

Three special bits deserve recognition:

  • sticky bit on a directory (drwxrwxrwt) lets users delete only their own files. This is why /tmp is shared safely. Set with chmod +t.
  • setgid on a directory makes new files inherit the directory's group. This is the standard shared-project pattern. Set with chmod g+s.
  • setuid on an executable runs it with the file owner's effective UID. It is potentially dangerous and should be rare. Find them with find / -perm -4000 -type f.
SELinux is a second gate

Traditional permissions and ACLs are not the whole story on RHEL. SELinux can deny access even when the mode bits allow it. You will learn to read ls -Z, getenforce, and AVC denials in the security lesson.
