SSH is strict about ownership and permissions. A key or directory that other users can write is a security problem, so sshd refuses it rather than guessing.

terminal · protect key material and validate sshd
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub
sudo sshd -t
sudo systemctl reload sshd

On RHEL, the service is sshd, not ssh. The daemon must be restarted or reloaded after a configuration change, and sshd -t should pass first. Look in /var/log/secure or journalctl -u sshd for authentication decisions.

RHEL 9 vs RHEL 10

Both releases enforce system-wide crypto policies and strict key permissions. RHEL 10 ships newer OpenSSH defaults, so avoid assuming an old RSA key or legacy algorithm will be accepted. Generate ed25519 keys unless a specific compatibility requirement says otherwise.
