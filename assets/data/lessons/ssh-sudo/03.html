sudo is a policy engine, not a binary that means "root". A grant should answer three questions: who, on which hosts, and which commands. Blanket ALL=(ALL) ALL is a valid admin choice, but it should be deliberate.

/etc/sudoers.d/webops · scoped delegation
%webops ALL=(ALL) /usr/bin/systemctl restart httpd
%webops ALL=(ALL) /usr/bin/systemctl status httpd

Prefer absolute command paths and avoid wildcards that can be abused to run unrelated commands. Validate with visudo -cf; the drop-in must not be world-writable, and a common production mode is 0440.

terminal · validate and inspect
sudo chown root:root /etc/sudoers.d/webops
sudo chmod 440 /etc/sudoers.d/webops
sudo visudo -cf /etc/sudoers.d/webops
sudo -l -U student
Do not lock yourself out

Keep an existing root session open while changing sudo policy. A syntax error in sudoers can disable sudo for everyone, and a bad sshd config can remove your remote path in.
