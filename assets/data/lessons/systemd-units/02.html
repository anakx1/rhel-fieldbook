A service unit has three useful sections. [Unit] describes identity, ordering, and dependencies. [Service] describes how to run the process. [Install] describes how enabling the unit attaches it to a target.

/etc/systemd/system/fieldbook.service
[Unit]
Description=Fieldbook health reporter
After=network.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/fieldbook-report
User=root

[Install]
WantedBy=multi-user.target

Type=oneshot is right for a command that runs and exits. A long-running daemon normally uses Type=simple or Type=notify. Use absolute paths in ExecStart; systemd does not inherit your interactive shell aliases or working directory. Add Restart=on-failure only when restarting is actually safe.

unit locations
/usr/lib/systemd/system/     package-owned units
/etc/systemd/system/         local units and drop-ins
/etc/systemd/system/foo.service.d/*.conf   local overrides

Do not edit package-owned units when a drop-in will do. systemctl edit creates a drop-in that survives package upgrades.
