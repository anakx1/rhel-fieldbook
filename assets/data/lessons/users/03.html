su switches user identity and normally requires the target user's password. sudo runs one command as another user according to a policy, normally authenticating with your own password. sudo is auditable, granular, and the correct default on RHEL.

On RHEL, members of the wheel group are typically granted full sudo access by the default configuration. Check before changing anything:

terminal · inspect sudo rights
sudo -l
getent group wheel

Never edit /etc/sudoers directly with a normal editor. A syntax error can lock everyone out of privilege escalation. Use visudo, which validates the file before saving, or add a drop-in file under /etc/sudoers.d/ with mode 0440.

example sudoers drop-in
# /etc/sudoers.d/analyst
analyst ALL=(ALL) ALL
%engineering ALL=(ALL) /usr/bin/systemctl restart httpd

The first rule grants full sudo. The second grants only one command to a group. Least privilege is not about refusing to grant access; it is about granting the smallest access that does the job.

Audit trail

sudo logs invocations. When something changes unexpectedly, "who ran what" is often answerable from the journal and sudo logs. Shared root passwords destroy that trail.
